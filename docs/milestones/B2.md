## 2. Correction to B1: the category routing defect

B1's published figures were measured with a defect in how Bastion routed Sigma logsource
categories to Windows event IDs. This section corrects them. The `b1` tag and its history
are unchanged; `docs/milestones/B1.md` section 5 carries a one-line pointer here.

**Cause.** `src/bastion/engine.py` maps each Sigma `category` to the Sysmon and PowerShell event
IDs it may run on. Two names were wrong (`raw_access_read` for the taxonomy's
`raw_access_thread`, `clipboard_change` for `clipboard_capture`) and 11 categories were absent
(`file_change`, `file_delete_detected`, `file_block_executable`, `file_block_shredding`,
`file_executable_detected`, `sysmon_error`, `ps_classic_start`, `ps_classic_provider_start`,
`ps_classic_script`, `ps_module`, `ps_script`). A category missing from the map put no event ID
restriction on its rules, so they were evaluated against every Windows event. The Raw Disk
Access rule (T1006, `raw_access_thread`, Sysmon Event ID 9) is written entirely as exclusions
(no positive selection), so on events that were never Event ID 9 it fired almost everywhere.
`rule_applies` (`src/bastion/engine.py`) only restricts a rule by event ID when its category
is in the map. Fixed in `0421b02` (11 categories added, 2 renamed), with a parametrized test
over the taxonomy names and one that confines a negation-only rule to its category
(`tests/test_engine.py`).

**Comparison.** `b1-baseline` is the run published in B1 (engine `c0782c5`). `b2-baseline` is
the same outcomes re-summarized under decisions 1 and 2 (`906b6b2`), so it adds the strict
figures and the SigmaHQ regression criterion without changing a single detection.

## 4. Lever a: auditd parsing (`c95e3cb`)

and interpreted (`ausearch -i`) records, keeps the enriched half after `\x1d`, accepts quoted,
single-quoted `msg`, brace-group and bare values, merges records by audit id across
interleaving (a 1,000-record window), decodes hex only where auditd hex-encodes, and takes the
command line from EXECVE alone. The normalizer sorts interpreted timestamps as UTC.

Parse completeness over the 65 attack_data auditd captures: before, 4 of 65 parsed completely

## 7. Lever d: tri-state evaluation (`d11c5d0`)

A rule that does not match is now `no_match` only when every field it reads is present.
Otherwise it is `not_evaluable`, counted per rule and per missing field, or `outside_source`
when the event shares none of the rule's fields (a webserver rule on a Sysmon event). Matches
are decided exactly as before; a per-event comparison on 3,077 events gave byte-identical
detections, and the bench confirms it: no capture changed outcome and every rate is identical
between `b2-after-c` and `b2-after-d`. Throughput cost on a mixed probe: about 22% (34.5
against 44.4 events per second).

### Findings and open items

- **F1. auditd `type` on merged events (B3), a rule-level regression in lever a.** A merged
  event takes the type of its first record, and in raw logs SYSCALL precedes EXECVE. On the
  own-lab logs the old parser still produced 145 EXECVE-typed exec events (1,695 were typed
  SYSCALL); the new parser produces none (1,840 SYSCALL). So the 28 SigmaHQ rules that require
  `type: 'EXECVE'` could fire on a few own-lab events before lever a and cannot fire there after
  it. In this bench the only firings lost were the 6 false positives in section 4, and the
  own-lab `shutdown -P now` was missed by both parsers, but the gap is now uniform rather than
  occasional. The held-out split is not affected: it has no
  own-lab captures, and all 1,323 attack_data exec events start with their EXECVE record. It
  affects the 30 dev own-lab captures and the own-lab background.
- **F2. Keyword maps with `|all` (B3).** 14 rules (for example Binary Padding - Linux,
  Credentials In Files - Linux) use `'|all': [...]`, a keyword search with the `all` modifier.
  Bastion reads it as a field with an empty name, so these rules never fire, and the
  evaluability check does not flag them. Lever d made this visible (264,248 pairs).
- **F3. EVTX `UserData` is not flattened (B3).** Fields under `UserData` (WMI-Activity 5858 and
  others) are unavailable to rules; one r2026-07-01 regression case fails on it.
- **4. Goodware over budget.** 34.74 per host-day on the replay and 22.43 on the own-lab
  background, all from SigmaHQ rules (section 3). Filtering or demoting them is Mason's call.
- **5.** README coverage text still quotes the 19.1 denominator 697; left for B8 as before.
- **6.** The attack_data `sha256` entries in `bench/manifest.toml` predate lever a's
  normalizer (section 4); refresh them in B3.
