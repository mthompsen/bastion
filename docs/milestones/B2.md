## 1. Decisions taken

From B1 section 7 (Mason, 2026-09-27 and 2026-11-10):

1. **Regression pass criterion.** The headline uses SigmaHQ's own runner semantics (at least
   the expected matches); Bastion's exact-count figure is reported beside it everywhere. Done
   in `f1c9515`.
2. **Headline detection rate.** Parent-aware: a rule tagged to the labelled technique, its
   parent or its sub-technique counts; sibling sub-techniques do not. Strict (exact tag) is
   reported beside it everywhere. Done in `f1c9515`.
3. **Raw Disk Access (T1006).** The goodware noise turned out to be a routing defect in
   Bastion, not a property of the rule (section 2). Mason accepted the routing fix in place of
   a filter document. A filter is written only if the post-fix benchmark shows the remaining
   goodware matches over the budget; the outcome is reported in section 3 either way. The
   filter mechanism itself shipped in `3ce4136`.
4. **Tag disputes.** No retagging. One-line summaries in `docs/tag-disputes.md`, draft
   upstream issue texts in `docs/tag-disputes-drafts.md`, nothing filed. Done in `f1c9515`.
5. **Local pack.** Only the 2 Windows rules are promoted to `test` (`f2081bb`): both have
   passing true-positive and true-negative fixtures and produced no goodware alerts. The 6
   Linux rules stay `experimental` because there is no Linux goodware corpus; the reason is
   recorded in `rules/README.md`.

`bench/results/b2-promote` is superseded: it re-summarized the B1 outcomes, so it predates
the routing fix, and it promoted all 8 local rules. See its `SUPERSEDED.md`.
