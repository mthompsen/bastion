Date: 2026-09-26. Prepared by Claude Code for Mason Thompsen. Follows `docs/milestones/B0.md`.

B1 delivers the harness the START_PROMPT asks for in section 10: `bastion bench`, a manifest
and split, loaders for SigmaHQ `regression_data`, EVTX-ATTACK-SAMPLES, Nextron evtx-baseline

## 2. Speed-up and its proof

Measured before B1: about 30 events per second against the Windows ruleset, so one
evtx-baseline host set was two to three hours. The matcher now compiles each condition once
per rule into a callable, caches parsed field specs and transformed candidate values, caches
compiled regexes (the `re` module's own cache holds 512 entries and a ruleset carries
thousands), and the engine reads each rule's pre-filter inputs once per scan. Semantics are
unchanged by construction: both operands of `and` and `or` are still evaluated, left first,
so evidence collection is identical; errors are raised at the same call with the same
messages.

| Probe (3,000 events, full Windows ruleset) | Before | After |
|:-|:-|:-|
| Security channel matching | 34 events/s | 63 events/s |
| Sysmon channel matching | 28 events/s | 47 events/s |
| Windows rule load | 24 s | 13 s |

Proof, all on Sigma `r2026-04-01` plus the 8 local rules, ATT&CK 19.1:

1. The test suite: 217 tests passed before and after the change (286 with the new bench tests).
2. The README canary: `bastion scan` on the BITS-job sample reports 3 detections across 2
   techniques, 6 events, 2,458 rules, 1 unsupported rule, before and after.
3. Per capture: the regression suite (163 outcomes) and the positives suite (380 outcomes)
   re-run after the change produced identical rule ids and match counts on every capture.
4. Per event: the `b0` matcher and the new matcher were each run over all 517 positive and
   regression files (278 EVTX-ATTACK-SAMPLES, 169 regression EVTX, 66 attack_data auditd
   logs, 5 Citadel audit logs; 43,337 events). Every (file, event index, rule id, matched
   fields) tuple was dumped and the two dumps are byte-identical: 2,352 detections, same
   sha256.

## 3. The seven regression failures, by cause

Regression pass rate: 152 of 159 evaluable SigmaHQ `regression_data` EVTX cases (95.6%,
95% CI 91.2% to 97.9%). Pass means Bastion's count equals `match_count` exactly, which is
the section 4 definition. SigmaHQ's own runner fails only on fewer matches and warns on more.
Ten cases skipped: 9 whose rule is in `rules-emerging-threats` and 1 in
`rules-threat-hunting`, trees Bastion does not cache yet. The pinned tag has no JSON cases.

| Rule | Expected | Actual | Cause | Class |
|:-|-:|-:|:-|:-|
| Anydesk Temporary Artefact (file_event) | 1 | 3 | Three events in the sample carry `user.conf` in `TargetFilename`; every one satisfies `contains`. Upstream's count is a minimum under its runner | Fixture expectation, not an engine defect |
| Cred Dump Tools Dropped Files (file_event) | 1 | 3 | `procdump64.exe`, `procdump64a.exe`, `procdump.exe` all match `endswith` | Fixture expectation |
| IE Change Domain Zone (registry_set) | 1 | 3 | Three `ZoneMap\Domains` writes with `Details` `DWORD (0x00000002)`, none in the filter list | Fixture expectation |
| Disable Administrative Share Creation at Startup (registry_set) | 1 | 2 | `AutoShareServer` and `AutoShareWks` both written to 0 | Fixture expectation |
| Potential NTLM Coercion Via Certutil.EXE (process_creation) | 1 | 0 | Rule value `' \\\\'` is Sigma-escaped for two literal backslashes (a UNC prefix). Bastion's `contains` treats the value literally, so it looks for four | Grammar gap: backslash escapes are only unescaped on the wildcard path of plain equality, not for `contains`, `startswith`, `endswith` |
| File And SubFolder Enumeration Via Dir Command (process_creation) | 1 | 0 | `CommandLine\|contains\|windash: 'dir*-s'`: the `*` inside a `contains` value is a wildcard in Sigma and a literal in Bastion (a documented subset limitation) | Grammar gap: wildcards inside `contains` values |
| Recon Command Output Piped To Findstr.EXE (process_creation) | 1 | 0 | `CommandLine\|contains: 'tasklist*\|*find'`, same wildcard-in-contains gap | Grammar gap |

Summary: 4 fixture-expectation mismatches where every counted event genuinely satisfies the
rule (under SigmaHQ's own criterion these pass, giving 156 of 159), 3 grammar gaps in the
documented subset (2 wildcard-in-contains, 1 escape handling), 0 engine defects, meaning no
case where the matcher's answer is wrong under the grammar it documents. Nothing was fixed;
the grammar gaps go to B2 (section 6 lever 1), and the expectation convention is a decision:
keep exact equality as section 4 says, or adopt SigmaHQ's at-least semantics.

## 4. Detection rate versus any-alert rate on the held-out split

Held-out split, 130 labelled positive captures (Sigma `r2026-04-01` plus 8 local rules,
ATT&CK 19.1, seed 20260926). The headline definition (section 4) counts a rule tagged to the
labelled technique or to its parent or sub-technique. The strict column counts exact tag
matches only. Both are reported; the headline definition is Mason's decision and was not
changed.

| Count | Strict (exact tag) | Parent-aware (headline) |
|:-|-:|-:|
| Detected | 29 of 130 | 33 of 130 |
| Any alerting rule fired | 75 of 130 | 75 of 130 |
| Alerted but not detected | 46 | 42 |
| No alerting rule fired | 55 | 55 |

The four parent-aware hits come from rules tagged at sub-technique level on captures labelled
at parent level or the reverse. There were no sibling mismatches (a rule tagged to a sister
sub-technique of the label) and no capture where the only alerts came from untagged rules.

The 42 alerted-but-undetected captures, mechanically: 16 fired rules tagged to a different
technique in the same tactic, 26 to a different technique and tactic. Read one by one (the
reviewer's judgment; every capture's bucket is listed in `docs/bench/b1-gap-appendix.md` so
any assignment can be disputed):

| Reading | Captures | Examples |
|:-|-:|:-|
| Side activity in the capture, label and rule both plausible for different behaviour | 30 | Discovery rules (whoami, systeminfo) on privilege-escalation samples; regsvr32 rules on the BITS-job sample; startup-folder rules on a timestomp sample |
| Rule tag disputes (rule fired on the labelled behaviour, its tag names another technique) | 4 | Mshta dropper rule tagged T1059.x; PowerShell Credential Prompt tagged T1059.001; RottenPotato-like tagged T1557.001; unquoted service path tagged T1547.009. Recorded in `docs/tag-disputes.md` |
| Label quality (sheet label coarse or wrong, rule plausibly right) | 8 | DCShadow capture labelled Application Shimming (T1138); KeePass credential theft labelled T1003 where rules say T1555.005; WMI lateral movement labelled T1021 where rules say T1047; remote scheduled task labelled T1021 where the rule says T1053.005 |

One rule dominates the noise: "Potential Defense Evasion Via Raw Disk Access By Uncommon
Tools" (T1006) fired on 20 of the 42 captures and accounts for 92 of the 279 cross-fired
alerts on the held-out split. It also appears on the goodware replay (section 6).

Of the 55 captures with no alert: 33 are attack_data auditd datasets, 24 of which contain no
EXECVE record at all (PROCTITLE, SYSCALL, PATH or SERVICE_STOP only), so no `CommandLine`
exists for a `process_creation` rule to read. Those are telemetry shape, not rule gaps, and
belong to B3. The other 22 are EVTX-ATTACK-SAMPLES files: several are Security-log-only
(Kerberos password spray 4771, 4663 file access, 7045 service, 4698 task) where the pinned
rules need Sysmon fields or counting, and the rest are true misses on Sysmon telemetry.

Label remaps: 46 of the 130 held-out captures carry labels that went through `revoked-by`
(T1088 to T1548.002, T1085 to T1218.011, T1089 to T1562.001 to T1685, and so on). Without the
remap every one of those would have been a false miss.

## 7. Decisions for Mason

1. **Regression pass criterion.** Keep exact equality (section 4) or adopt SigmaHQ's
   at-least semantics; the four expectation mismatches in section 3 hinge on it.
2. **Headline detection definition.** Strict 29 of 130 versus parent-aware 33 of 130 (section
   4). Not changed here.
3. **Noisy upstream rule.** "Potential Defense Evasion Via Raw Disk Access By Uncommon Tools"
   is the top cross-firer and appears on goodware. Section 6 lever 8 says filter with a
   justification, never edit; that is B4 work and needs a yes.
4. **Tag disputes.** Four candidates in `docs/tag-disputes.md`; report upstream or leave open.
5. **Local pack.** Stays hunting class (decision 4 in B0). Promotion needs Linux benign
   evidence beyond Citadel's background; none of the 8 local rules fired on the goodware
   Windows set (6 are Linux rules).

## 8. What B1 did not do
